## 배포 순서

```
1. 056_weekly_honor_gardener.sql   앱 배포 전에 (구버전은 영향 없음)
2. 0.25.0 을 스토어에 올리고 출시 완료까지 기다린다
3. 버전 게이트 올리기               ← 출시가 끝난 뒤에만
```

3번은 두 컬럼을 같이 올립니다. 한쪽 스토어만 끝났으면 끝난 쪽만.

```sql

   set latest_version = '0.25.0', min_version = '0.25.0', updated_at = now()
 where platform in ('android', 'ios');
```

## 선생님께 (스토어에 올리지 않는 내용)

### 왜 바꿨나

명예의 전당은 한 달 단위라 한 번 정해지면 거의 바뀌지 않았습니다. 학생 입장에서는
월 중순만 넘어가도 "이번 달은 이미 끝났다" 가 됩니다. 일주일로 끊고 매번 새로
계산하면 월요일마다 모두에게 기회가 생깁니다.

### 점수 (100점)

| 항목 | 배점 | 기준 |
|---|---|---|
| 꾸준함 | 40 | 이번 주 **지금까지의 수업일** 중 점검한 날의 비율 |
| 실천 | 30 | 이번 주 자기점검 O/X 평균 점수 × 0.3 |
| 칭찬 | 30 | 이번 주 받은 칭찬 1회당 10점, **3회까지** |

- **지금까지의 수업일**로 나누므로 월요일 아침 첫 점검이면 꾸준함 40점 만점입니다.
  휴일이 낀 주도 불리하지 않습니다.
- 칭찬은 3회까지만 셉니다. 칭찬을 몰아 받아도 점검을 안 하면 이길 수 없습니다.
- 이번 주에 **한 번이라도 점검한 학생만** 후보입니다.
- 졸업·전출 처리된 학생은 빠집니다.
- 048 이전 날짜 조작으로 남은 주말 기록은 세지 않습니다.

### 동점

만점 가까이에서 동점이 자주 납니다. 매일 점검하고 전부 O 를 한 학생은 칭찬이 없으면
모두 70점입니다. 그래서 칭찬 → 점검일수 → 평균점수 순으로 가르고, 그래도 같으면
**그 주 안에서만 고정된** 무작위로 정합니다.

그냥 무작위로 하면 새로고침할 때마다 1위가 바뀌어 보입니다. 사실상 **칭찬이 순위를
가르는 구조**라서, 선생님 칭찬이 곧 명예 식집사로 이어집니다.

### 이름은 서버에서 가립니다

`김민수 → 김*수`, `이서 → 이*`, `남궁민수 → 남**수`

앱에서 가리면 네트워크 응답에는 실명이 그대로 담깁니다. 마음먹은 학생은 다른 반 친구의
실명을 볼 수 있습니다. 그래서 서버가 가린 이름만 보냅니다.

### 등수는 보여주지 않습니다

띠를 누르면 내 이번 주 점수가 나오는데, **우리 반 몇 등인지는 보여주지 않습니다.**
"우리 반 23등" 은 하위권 학생에게 벌처럼 읽힙니다. SWPBS 의 방향과 반대입니다.

1등과의 차이도 **20점 이내일 때만** "명예 식집사까지 12점!" 으로 보여줍니다. 차이가
크면 따라잡을 마음보다 포기가 먼저 옵니다. 그때는 점검 일수와 칭찬 수만 보여줍니다.

### 언제 바뀌나

- 앱을 열 때
- 홈 화면에서 아래로 당겨 새로고침할 때
- 홈을 열어둔 동안 5분마다
- 자기점검을 제출한 직후

이번 주에 아직 아무도 점검하지 않았으면(월요일 새벽, 휴일 주간) 빈 띠 대신
**지난주 최종 결과**를 "지난주 명예 식집사" 로 보여줍니다.

### 확인용

```sql
select grade, class_num, mask_name(nickname) as 이름, score,
       days_done, avg_pct, praise_cnt
  from weekly_honor_rank('<school_id>', date_trunc('week', now())::date)
 where rn = 1 order by grade, class_num;
```
