# 0.25.0 출시노트

이 주의 명예 식집사를 학생 홈에 띄우고, 친구끼리 칭찬을 주고받는 칭찬 우체통을 열었습니다.

## 배포 순서

```
1. 056_weekly_honor_gardener.sql   앱 배포 전에
2. 057_praise_mailbox.sql          앱 배포 전에
3. 0.25.0 을 스토어에 올리고 출시 완료까지 기다린다
4. 버전 게이트 올리기               ← 출시가 끝난 뒤에만
```

056·057 은 먼저 실행해도 구버전 앱에는 영향이 없습니다. 반대로 SQL 없이 앱만
올라가면 명예 식집사 띠는 숨겨지고 칭찬 우체통은 "열지 못했어요" 가 뜹니다.

4번은 두 컬럼을 같이 올립니다. 한쪽 스토어만 끝났으면 끝난 쪽만.

```sql
update app_releases
   set latest_version = '0.25.0', min_version = '0.25.0', updated_at = now()
 where platform in ('android', 'ios');
```

## 선생님께 (스토어에 올리지 않는 내용)

# 1. 이 주의 명예 식집사

### 왜 바꿨나

명예의 전당은 한 달 단위라 한 번 정해지면 거의 바뀌지 않았습니다. 학생 입장에서는
월 중순만 넘어가도 "이번 달은 이미 끝났다" 가 됩니다. 일주일로 끊고 매번 새로
계산하면 월요일마다 모두에게 기회가 생깁니다.

### 점수 (100점)

| 항목 | 배점 | 기준 |
|---|---|---|
| 꾸준함 | 40 | 이번 주 **지금까지의 수업일** 중 점검한 날의 비율 |
| 실천 | 30 | 이번 주 자기점검 O/X 평균 점수 × 0.3 |
| 칭찬 | 30 | 이번 주 **선생님께** 받은 칭찬 1회당 10점, **3회까지** |

- **지금까지의 수업일**로 나누므로 월요일 아침 첫 점검이면 꾸준함 40점 만점입니다.
  휴일이 낀 주도 불리하지 않습니다.
- 칭찬은 3회까지만 셉니다. 칭찬을 몰아 받아도 점검을 안 하면 이길 수 없습니다.
- **칭찬 우체통의 친구 칭찬은 여기 들어가지 않습니다.** 친구끼리 주고받아 점수를
  올리는 일을 막기 위해서입니다.
- 이번 주에 **한 번이라도 점검한 학생만** 후보입니다.
- 졸업·전출 처리된 학생은 빠집니다.

### 동점

만점 가까이에서 동점이 자주 납니다. 매일 점검하고 전부 O 를 한 학생은 칭찬이 없으면
모두 70점입니다. 그래서 칭찬 → 점검일수 → 평균점수 순으로 가르고, 그래도 같으면
**그 주 안에서만 고정된** 무작위로 정합니다. 사실상 **선생님 칭찬이 순위를 가릅니다.**

### 이름은 서버에서 가립니다

`김민수 → 김*수`, `이서 → 이*`, `남궁민수 → 남**수`

앱에서 가리면 네트워크 응답에는 실명이 그대로 담깁니다.

### 등수는 보여주지 않습니다

띠를 누르면 내 이번 주 점수가 나오는데, **우리 반 몇 등인지는 보여주지 않습니다.**
"우리 반 23등" 은 하위권 학생에게 벌처럼 읽힙니다. 1등과의 차이도 **20점 이내일
때만** 보여줍니다.

### 언제 바뀌나

앱을 열 때 · 홈에서 아래로 당겨 새로고침할 때 · 홈을 열어둔 동안 5분마다 ·
자기점검을 제출한 직후. 이번 주에 아직 아무도 점검하지 않았으면 "지난주 명예
식집사" 를 보여줍니다.

# 2. 칭찬 우체통

**학생 홈 왼쪽 메뉴 → 칭찬 우체통** · **선생님 대시보드 → 학급 칭찬 우체통**

### 원칙

| 결정 | 내용 |
|---|---|
| 승인 | 담임 승인 없이 바로 전달 |
| 쓰는 방식 | **문장 고르기만.** 학생이 입력하는 글자가 없음 |
| 받는 사람 | **같은 반 친구만** |
| 이름 공개 | 보내는 학생이 **익명 / 이름 밝히기** 중 선택 |
| 횟수 | 일주일에 3번, **서로 다른 친구에게만** |
| 포인트 | 없음 |

### 금칙어 필터가 필요 없는 이유

학생이 쓰는 글자가 한 자도 없어서 걸러낼 것이 없습니다.

더 중요한 것은 **앱이 문장을 보내지 않는다는 점**입니다. 앱은 "help_1" 같은 문장
번호만 보내고, 서버가 자기 목록에서 문장을 꺼내 씁니다. 앱을 조작해도 목록에 없는
말은 들어갈 수 없습니다. 필터는 돌려 말하면 뚫리지만 이 구조는 뚫릴 곳이 없습니다.

### 문장 20개

| 분류 | 문장 |
|---|---|
| 도움 | 모르는 문제를 친절하게 알려줬어요 · 무거운 짐을 같이 들어줬어요 · 떨어뜨린 물건을 주워줬어요 · 준비물을 기꺼이 빌려줬어요 |
| 배려 | 이야기를 끝까지 들어줬어요 · 차례를 먼저 양보해줬어요 · 속상한 친구를 위로해줬어요 · 함께 하자고 먼저 불러줬어요 |
| 책임 | 청소를 끝까지 꼼꼼하게 해줬어요 · 맡은 역할을 성실하게 해냈어요 · 교실 정리를 먼저 나서서 도왔어요 · 정해진 시간과 약속을 잘 지켰어요 |
| 수업 | 모둠 활동에 적극적으로 참여했어요 · 용기 있게 발표를 해냈어요 · 수업에 집중하는 모습이 멋졌어요 · 친구의 발표에 박수를 보내줬어요 |
| 바른 행동 | 옳은 일을 하려고 용기를 냈어요 · 규칙을 잘 지켜서 모범이 됐어요 · 먼저 밝게 인사해줬어요 · 고맙다는 말을 먼저 해줬어요 |

고르면서 뺀 것들이 있습니다.

- **"따뜻하게", "다정하게" 같은 수식어** — 연애 뉘앙스로 읽힐 수 있어서
- **"먼저 사과했어요"** — 받는 학생이 먼저 잘못했다는 뜻이 섞여서
- **"혼자 있는 친구에게 말을 걸어줬어요"** — 다른 학생을 외톨이로 지목하게 돼서
  "함께 하자고 먼저 불러줬어요" 로 바꿨습니다

문장은 `praise_mail_templates` 표에 있습니다. 바꾸거나 더하고 싶으시면 말씀해 주세요.

### 익명의 범위

**친구에게** 익명입니다. **선생님께는** 익명 편지도 보낸 학생 이름이 보입니다.
학생 화면에도 "선생님은 익명 편지도 누가 보냈는지 확인할 수 있어요" 라고 적어뒀습니다.
장난을 막는 가장 확실한 장치입니다.

익명 편지는 받은 학생에게 가는 응답에 보낸 사람 이름을 **아예 싣지 않습니다.**
편지 표는 학생이 직접 읽을 수 없게 막아뒀습니다. 직접 읽을 수 있으면 보낸 사람
id 가 그대로 보이기 때문입니다.

### "사실이 아니에요"

받은 학생이 편지 옆 메뉴에서 누르면

1. 그 편지가 받은 학생 화면에서 바로 사라집니다
2. **담임 선생님께 알림**이 갑니다 (담임 미지정이면 관리자 선생님께)
3. 학급 칭찬 우체통에 **빨간색 "학생이 숨김"** 으로 남습니다

선생님도 학급 칭찬 우체통에서 편지를 숨길 수 있습니다.

### 누가 볼 수 있나

| | 볼 수 있는 것 |
|---|---|
| 받은 학생 | 받은 편지 (익명이면 보낸 사람 이름 없음) |
| 보낸 학생 | 이번 주에 보낸 편지 |
| 다른 학생 | **아무것도 없음.** 누가 몇 통 받았는지 순위도 없음 |
| 담임 선생님 | 우리 반에서 오간 편지 전부, 보낸 학생 실명 포함 |
| 관리자 선생님 | 모든 학급 |
