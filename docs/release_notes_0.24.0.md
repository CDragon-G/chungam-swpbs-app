## 선생님께 (스토어에 올리지 않는 내용)

### 1. 내가 보낸 칭찬

칭찬을 보내면 학생에게만 알림이 갔습니다. 선생님 쪽에는 스낵바가 잠깐
떴다 사라져서, 같은 학생을 두 번 칭찬하거나 보낸 줄 알았는데 안 보낸 일이
생겼습니다.

- 칭찬을 보내면 **선생님 알림함에도** 한 건 남습니다
- **일괄 칭찬은 인원수만큼이 아니라 한 건**으로 남습니다
  (60명에게 보내도 알림은 "60명에게 칭찬을 보냈어요" 하나)
- 알림을 누르면 **내가 보낸 칭찬** 목록으로 갑니다
- 대시보드에도 들어가는 버튼을 넣었습니다

알림 종류를 `praise` 가 아니라 `praise_sent` 로 둔 이유가 있습니다.
알림 중복 방지 키가 (학교, 종류, 사건 id) 라서, 학생에게 간 알림과 종류까지
같으면 선생님 알림이 조용히 버려집니다.

### 2. 새 학년도 진급 처리

**명단 관리 → 새 학년도 진급 처리**

지금까지는 3월에 새 명렬표를 그냥 올리면 세 가지가 어긋났습니다.

**1) 진급이 반영되지 않습니다.** 프로필의 학년·반·번호는 가입할 때 한 번
쓰고 그 뒤로 아무도 고치지 않았습니다.

**2) 신입생이 가입을 못 합니다.** 명단의 고유키가 (학교, 학년, 반, 번호)
즉 '자리' 라서, 작년 1학년 3반 5번 자리가 잠긴 채로 남습니다. 새 1학년
3반 5번 학생은 "이미 가입에 사용된 학번이에요" 를 만납니다.

**3) 계정이 갈라집니다.** 진급한 학생 앞에 빈 자리가 새로 생겨서, 학생이
다시 가입하면 포인트 0짜리 두 번째 계정이 만들어집니다.

진급 처리는 자리를 새로 만드는 대신 **사람을 옮깁니다.**

| 대상 | 처리 |
|---|---|
| 이름이 같고 학년이 정확히 +1 | 자리를 그대로 이동. **PIN 유지** — 다시 가입할 필요 없음 |
| 새 이름 | 신입생. 새 자리 + 새 PIN |
| 새 명렬표에 없는 사람 | 졸업·전출. 자리를 비우고 프로필에 `left_at` 표시 |

**반드시 미리보기가 먼저 나옵니다.** 누가 어디로 가는지 전부 보여드린 뒤에만
실행 버튼이 열립니다.

### 동명이인이 있으면 실행되지 않습니다

같은 학년에 이름이 같은 학생이 있으면 자동으로 이을 수 없습니다.
이때는 **아예 실행하지 않습니다.** 그 학생들만 빼고 돌리면 자리가 어긋나
다른 학생의 이동까지 막히기 때문입니다. 400명을 반쯤 옮겨 놓고 멈추는 것보다
손대지 않고 멈추는 편이 낫습니다.

미리보기에 해당 학생이 표시됩니다. **학생 관리에서 그 학생들의 학년·반·번호를
먼저 맞춘 뒤** 다시 실행하세요. 이를 위해 학생 한 명의 학번을 직접 고치는
기능도 함께 넣었습니다 (`set_student_class`).

유급한 학생도 학년이 +1 이 아니라서 같은 방식으로 걸립니다. 미리보기에서
확인하고 수동으로 처리하세요.

### 졸업 처리된 학생은 어떻게 되나

- 기록·포인트·칭찬은 **하나도 지워지지 않습니다**
- `profiles.left_at` 에 시각만 남습니다
- **참여율 분모에서 빠집니다** — 3월마다 참여율이 근거 없이 무너지던 문제가 사라집니다
- 자기점검을 할 수 없게 됩니다

전출인 줄 알았는데 아니었다면 되돌릴 수 있습니다.

```sql
select undo_student_leave('<user_id>');
```

### 아직 없는 것

학년도가 바뀌어도 **학급 편성(담임-학급 연결)** 은 그대로입니다. 담임 선생님이
바뀌는 것은 따로 정리하셔야 합니다.
